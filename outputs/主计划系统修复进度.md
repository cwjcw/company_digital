### Root cause

重复发生在**投影分组阶段**，不在源数据主键阶段：去重/聚合身份与 `ON CONFLICT` 目标键不一致。

1. `order_items` 的 `summarized` CTE 把 `item_name`、`customer_code`、`customer_name`、`source_order_id` 一起放进 `GROUP BY`，而目标唯一键只有 (期间, 订单, 品项)。同一订单号/品项/月份下品名或客户字段不同的两条 ERP 行因此生成两组输入，却指向同一条 `order_items`，同一条 INSERT 内写同一目标两次 → PostgreSQL 直接报 `ON CONFLICT DO UPDATE command cannot affect row a second time`。
2. `orders` 的 `headers` 用 `DISTINCT ON(source_system,source_database,source_order_id)` 去重，而目标键是 `(source_database,order_number)`；同一订单号下多个 ERP 订单 ID 时同样会在一条 INSERT 内命中同一目标。

隔离复现（临时库，已删除）：相同两行输入用旧分组键（含 item_name）执行即报同一错误，用目标身份分组则成功合并为 1 行、数量 2。

### 业务合并规则（数据证明）

`order_items` 的正式身份是“租户内一张订单的一个品项每月一条记录”，生产既有数据中所有多行组（14/13/11/10/9/8/7/6 行）的 `production_quantity` 都等于对应 ERP 订单行数量之和，因此合并规则确定为：数量 `sum`、交期 `min`、品名/客户/来源订单 ID 取 `modified_at` 最新（同刻按 `source_id` 倒序）的一条；`sales_orders` 仍按 ERP 行主键逐行保留，不丢任何 ERP 行。
