## 当前任务 KN-PRINT-001（已完成）：KDOS 全平台统一表格打印

任务名称：KDOS 全平台统一表格打印
当前状态：**已完成**（2026-09-17，含选中打印缺陷修复与真实浏览器 UAT 10/10 通过）。

### 缺陷根因（用户报告：勾选 1 条后打印预览仍是全部记录）

1. **前端根因**：`KdosDataTable` 同时存在两个打印入口——工具栏「打印筛选结果」调用 `runPrint()`（无 selectedIds，FILTERED）与选择工具栏「打印已选（N）」（SELECTED）；用户点顶部按钮就打印了全部筛选结果。
2. **前端次级根因**：用户管理、营销、数据中心等页面传入自定义 `rowSelection`，覆盖了平台内部选择状态，导致平台侧 `selectedRowKeys` 恒为空，「打印已选」读不到选择（等价于退化打印全部）。
3. **后端根因**：`TablePrintService.normalizeIds()` 用全局 UUID 正则过滤 ID，且用 `selectedIds.length > 0` 隐式推断模式——客户端 ID 一旦被过滤成空数组，就静默退化为 FILTERED 打印整表。另发现 SELECTED 的 count 分支丢失页面上下文（`query` 未传入）。

### 修复

1. **单一主打印入口**：工具栏只保留一个按钮，未选中显示「打印筛选结果」（FILTERED），有选中自动变为「打印已选（N）」（SELECTED）；删除 selection toolbar 里重复的打印按钮。
2. **选中优先强规则**：`rangeType` 由选择状态显式推导（SELECTED 优先），不再用 selectedIds 长度推断。
3. **显式协议**：`/table-prints/manifest` 与 `/table-prints/render` 都要求/接受 `rangeType`；`FILTERED` 一律忽略 selectedIds；`SELECTED` 的空/非法 ID → 400，绝不退化。
4. **resource 级稳定主键**：`TableFilterSource.recordKey = { field, type: uuid|text|integer|bigint }`（默认 uuid id），通用打印 SQL 按真实主键参数化查询与排序，不再假设 UUID。
5. **provider 支持 SELECTED**：主计划 `list()` 新增 `ids` 条件（打印已选同样走 ACTUAL/PENDING 正式 Query）；users 走 `listUsersPage` 的 `ids`；SELECTED 的 count 也带上 page context（部门/状态/角色/视图）。
6. **选择状态同步**：页面自定义 `rowSelection` 会被平台包装，选择变化同步进平台选择状态（打印与选择语义一致）。
7. **Skill 固化**：3.1.0.3 打印章节新增 2.1–2.7 条强制规则（单一入口、选中优先、显式 rangeType、禁止 fallback、stable ID 不假设 UUID、rowSelection 同步、选中 N 只打印 N）。

### Root cause

重复发生在**投影分组阶段**，不在源数据主键阶段：去重/聚合身份与 `ON CONFLICT` 目标键不一致。

1. `order_items` 的 `summarized` CTE 把 `item_name`、`customer_code`、`customer_name`、`source_order_id` 一起放进 `GROUP BY`，而目标唯一键只有 (期间, 订单, 品项)。同一订单号/品项/月份下品名或客户字段不同的两条 ERP 行因此生成两组输入，却指向同一条 `order_items`，同一条 INSERT 内写同一目标两次 → PostgreSQL 直接报 `ON CONFLICT DO UPDATE command cannot affect row a second time`。
2. `orders` 的 `headers` 用 `DISTINCT ON(source_system,source_database,source_order_id)` 去重，而目标键是 `(source_database,order_number)`；同一订单号下多个 ERP 订单 ID 时同样会在一条 INSERT 内命中同一目标。
