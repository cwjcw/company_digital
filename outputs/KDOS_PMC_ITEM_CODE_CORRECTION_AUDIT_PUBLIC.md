# KDOS PMC 品项编码更正调查：脱敏技术摘要

状态：只读调查已完成；修复未执行，等待用户审核。

本摘要仅用于GitHub同步。完整订单号、品项编码、源系统行ID、业务UUID、数量、报工/入库事实及具体日期保留于本机受限报告 `outputs/KDOS_PMC_ITEM_CODE_CORRECTION_AUDIT.md`，不提交Git。此处不以脱敏摘要替代完整影响清单或生产实施预检查。

## 已确认的技术边界

- PMC历史初始化身份与正式ERP来源身份需要分开核验；源数据当前正确，不代表PMC历史快照会自动更正。
- `MasterPlanSyncService.projectOrders()`既有更新分支排除订单号及品项编码，重跑同步不能代替身份更正。
- 部分计划保存编码快照，部分执行记录通过稳定UUID关联；只修改单表会造成显示、统计和入库匹配不一致。
- 订单分配归档和计划投影暂停是现有业务边界，不能为了更正品号恢复归档或重启全量投影。
- 更正必须保留原记录UUID、交期编码、分配/计划数量、生产报工、外部事实和既有操作审计；不能删除重建、全库替换或跨订单更新。

## 推荐后续实现

1. 专用Application Command提供只读预检查及显式确认，以租户、固定记录UUID和ERP稳定来源身份限定范围，校验权限、字段权限、数据范围、版本及唯一键冲突。
2. 在单事务内维护必要来源别名、所有已核实业务编码快照及交期计数器，保留原始来源键和全部事实字段。
3. 复用既有计算公式实现限定范围派生计算；归档月计划的汇总处理单独获得业务确认，不混入编码更正。
4. 逐行及批次审计记录真实操作人、原值/新值、原因、影响ID和版本；幂等收据同事务提交，失败整批回滚。
5. 更正与既有同步、报工及其他写入使用真正共享的并发协议；旧文件重放和旧码再次写入须明确校验。
6. 最小方案复用现有来源别名、审计和幂等结构，无需结构Migration；如另需持久沿革或权限结构，另行评估前向Migration。
