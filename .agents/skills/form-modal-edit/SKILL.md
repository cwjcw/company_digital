# KDOS 弹窗编辑表单

在 KDOS 新建或修改表格行级编辑、新增/查看/编辑弹窗时使用。先读取项目 `AGENTS.md`、`.agents/skills/kdos-form-platform/SKILL.md`、`.agents/skills/kdos-form-validation/SKILL.md` 及对应业务 docskill；布局结构同时遵守 `.agents/skills/form-layout-design/SKILL.md`。本 Skill 约束通用交互，不替代业务生命周期和权限规则。

## 入口与数据加载

- 业务表格使用明确的行级“编辑”入口。共享表格可以提供可选 `rowActions` 扩展点；调用方按资源权限、字段权限和记录范围控制按钮显示。不要把通用单元格编辑模式当作业务弹窗编辑入口。
- 点击编辑后，以稳定记录 ID 请求现有详情 API。详情请求成功后再打开并回填表单；加载失败时保持编辑窗关闭并给出错误。不得仅使用列表行或过期详情缓存作为编辑数据源。
- 新增、查看、编辑复用相同字段组件、业务分组和布局。只读字段显示只读状态，不注册无权限可写控件；隐藏字段不得被空值覆盖。后端每次仍重新检查租户、资源操作、记录数据范围、字段权限和业务状态。
- 编辑保存携带服务端返回的 `version`/`expectedVersion`。冲突时保留用户输入并提示刷新或重新加载，不自动覆盖并发变更。
- 关闭/取消应遵守项目现有未保存数据处理；提交中防止重复提交，成功后刷新列表和当前详情。

## 主子表与重复提交

- 先在业务 docskill 明确关联方向、允许修改的子字段、创建/移除条件、已开始/已完成保护、并发版本及删除语义。
- 用稳定子记录 ID 更新原行，不能通过删除后重建来改字段；保留业务编号、ID、审计历史和所有未提交字段。新增子记录应有唯一编号、权限/范围校验及必要的通知 outbox。
- 若提交代表子项完整集合，必须区分“未授权或不可见的既有子项”与“用户明确移除的子项”。不得因为权限裁剪造成误删；受保护子项遇到变更/移除时应整笔拒绝。
- 主表、子表写入、软删除、审计与 outbox 应在同一事务内。具副作用的创建/关联同步使用 `Idempotency-Key`；重复相同请求返回原结果，复用同一 key 但内容不同则冲突。
- 对开始执行、已有业务事实或完成状态的记录按业务规则阻止编辑/删除。不得由前端隐藏入口代替后端状态校验。

## 附件与布局

- 详情 API 返回附件元数据；编辑时保持原附件可见，不要求为未变更附件重新上传。替换、移除仍需后端验证附件用途、租户、原记录引用及上传人/权限。
- 弹窗标题和底部操作栏保持可见，内容区独立纵向滚动并控制最大高度；桌面使用适合字段密度的列数，中等容器降为两列，窄容器为一列。长文本、证据附件和关联子表按业务设计跨满宽度，明细表可在内部横向滚动。
- 新建、编辑、查看使用一致的业务顺序、字段标签和分组；动作文案区分保存草稿、提交/完成等生命周期转移。

## 验证

- 覆盖列表编辑入口、按 ID 重新读取、加载失败不打开、权限隐藏与后端拒绝、编辑回填、保存后重新读取、版本冲突、附件保留、主子表新增/修改/移除、重复请求及已开始/已完成保护。
- 结合容器实际尺寸验证宽屏、两列和窄屏；验证键盘操作、滚动区域、固定操作栏和错误提示。
- 依照 `kdos-form-validation` 选择聚焦验证层级。区分单元/集成测试、浏览器验证、生产部署和生产业务验收；没有获准的生产测试数据时不得伪造或写入合成记录。

## 关联字段回填补充（2026-11-21）

远程搜索和级联字段按详情真实值回填，不依赖当前候选分页；不能因候选未加载、源记录停用或字段隐藏而静默清空历史值。父项由用户变更时清除不匹配子值并提示；初始化回填不应触发清理。保存必须经服务端重复验证，并保持原有附件、主子ID、版本及状态保护。
