# KDOS 表单与权限开发规范

把本文件视为凯南信息化平台中“表单设计—数据管理—权限管理”功能的强制产品与工程规范。实现、修改、审查或测试相关代码时，遵守下列规则。

## 1. 工作方式

1. 先检查当前仓库结构、现有实现、数据库迁移、接口、测试和未提交改动，再决定修改范围。
2. 优先复用现有技术栈、组件、字段定义和公共服务；不要为了套用本文而无理由重写正常模块。
3. 把本文中标为“固定”“必须”“不得”的内容视为验收条件，不得自行弱化。
4. 截图已确认的交互和权限状态优先于通用产品习惯；不要擅自增加截图中不存在的入口。
5. 遇到本文未定义且会显著改变业务结果的规则时，先列出缺口并询问；不要编造业务规则。
6. 前端只负责交互提示和视觉禁用，后端始终是权限、数据范围和字段安全的最终边界。
7. 修改后至少运行与改动相关的 lint、typecheck、单元测试和构建；无法运行时明确说明原因和未验证范围。
8. 输出结果时说明：修改了什么、关键规则如何落地、验证结果、仍存在的真实风险。

## 2. 核心范围与术语

- 租户：所有查询、写入、导出、广播、审计和缓存的第一层隔离边界。
- 表单：字段定义、布局、数据记录和权限组的归属单位。
- 权限组：对操作权限、字段权限、数据权限的组合定义。
- 授权对象：稳定 ID 标识的成员、部门或角色。
- 系统预置权限组：内部类型固定，只有显示名称可改。
- 自定义权限组：管理员可配置名称、说明、操作、字段和数据范围。
- 本人数据：`创建人 = 当前登录用户`，由后端根据认证身份动态解析。
- 全部数据：当前租户与当前表单内的全部数据，不得突破租户边界。

## 3. 数据表统一规则

### 3.1 表格能力

- 支持双层分组表头、横向虚拟滚动和大数据量虚拟渲染。
- 对主计划类宽表固定关键列；至少保证序号、订单号、品号、品名在横向滚动时可定位。
- 支持筛选、排序、搜索、列显示/隐藏、列宽调整和个人视图保存。
- 支持方向键、Tab、Enter、双击编辑、复制粘贴、TSV 多单元格粘贴、撤销/重做和查找。
- 支持单元格编辑、字典下拉、日期选择、数字校验、批量粘贴和批量保存。
- 图片字段显示缩略图并支持预览；上传、替换和删除必须受字段权限与附件权限控制。
- 保存失败必须定位到具体记录和字段并显示原因，不得只提示“保存失败”，也不得整页静默失败。

### 3.2 字段与数据类型

- 每个字段使用不可变的 `field_key`；显示名称修改不得改变字段身份。
- 未注册的 `field_key` 不得写入数据库。
- 订单号、品号、关联信息、供应商名称等标识值按字符串保存，保留前导零。
- 关联信息可由订单号与品号生成，但数据库仍须建立独立的业务唯一约束。
- 日期使用 ISO `YYYY-MM-DD`，数据库使用 `date`；不要把纯日期误存为带时区时间。
- 数量根据业务使用整数或 decimal；所需天数必须允许 `0.5` 等小数。
- 金额使用 PostgreSQL `numeric` 或等价精确十进制类型，禁止用浮点数处理金额。
- 明确区分空字符串、`null` 和数值 `0`。
- 图片与附件在数据库中只保存元数据、相对路径或受控 URL，不保存前端临时地址。

### 3.3 强制系统字段

每张业务数据表必须包含且只包含以下四个系统审计字段，顺序固定：

- 创建人
- 创建时间
- 更新人
- 更新时间

这四个字段由系统维护，必须满足：

- 在查看权限允许时可见，但永远不可编辑。
- 不得通过新增表单、数据表格、批量修改、导入、API、WebSocket 或任何权限配置修改。
- 后端必须忽略或拒绝客户端对这些字段的赋值和篡改。
- 创建人和更新人在数据库中保存稳定用户 ID；表格、详情、导出等用户界面必须通过通讯录显示姓名，不得显示 ID 编号，也不能把姓名作为身份依据。
- 用户离职、停用或改名后，历史数据仍应正确关联原用户记录。
- 首次创建记录时，创建人必须等于更新人，创建时间必须等于更新时间；后续修改只更新更新人和更新时间。
- 不得设置 `审计时间`、`auditedAt` 或 `audited_at` 业务表字段。操作审计仍写入独立审计日志，并与关键业务写入处于同一事务。

### 3.4 保存与并发

- 在后端事务中完成权限校验、字段校验、数据写入、必要的派生计算和审计记录。
- 使用版本号或等价机制实现乐观锁；冲突返回明确的 409 响应和当前服务端版本。
- 保存成功后以服务端返回值覆盖客户端预览值。
- 实时广播前再次按接收者的租户、数据范围和字段权限裁剪数据。

## 4. 权限管理页

### 4.1 权限组卡片

每个权限组以独立卡片显示，包含：

- 权限组显示名称。
- 已授权的成员、部门和角色区域。
- 适用于该组类型的操作，例如编辑、复制、其他设置、删除和启停开关。

规则：

- 卡片排序只影响展示顺序，不影响权限优先级。
- 系统预置权限组不得因改名而改变能力。
- 自定义权限组可以完整编辑；系统预置权限组只有名称可编辑。
- 权限组停用后，只移除该组贡献的权限，不影响用户从其他组获得的权限。
- 删除、停用和批量变更必须经过后端校验并写入审计。

### 4.2 授权对象与权限叠加

同一用户可以同时通过以下来源获得权限：

- 直接选择为成员。
- 所属部门。
- 所属角色。
- 其他已启用权限组。

有效授权按来源并集计算：

```text
用户有效权限 =
直接成员权限
∪ 部门权限
∪ 角色权限
∪ 其他已启用权限组权限
```

补充规则：

- 部门和角色授权是动态关系；成员加入或离开后，有效权限随组织关系变化。
- 如果部门和成员同时被选择，两条授权关系都要保留，移除部门授权不能连带删除个人授权。
- 离职、停用或被移出租户的用户立即失去有效权限；历史配置和审计记录保留。
- 不得因姓名相同把历史权限转移给新用户。
- 权限计算和缓存键必须包含租户、表单、用户与版本信息；变更后立即失效相关缓存。

## 5. 添加成员流程

添加成员必须是两步流程。

### 第一步：选择授权对象

- 支持选择成员、部门或角色。
- 未选择任何对象时，“确定”按钮禁用。
- 选择结果保存稳定 ID，不得只保存名称。
- 成员标签使用左右两栏：左侧显示“全部成员”和组织架构树；点击部门筛选右侧成员。
- 右侧显示当前范围成员，顶部显示“已选 N/M”。
- 每名成员显示头像、姓名和复选框。
- 当前结果提供全选框，并正确显示全选、半选和未选状态。
- 点击“确定”后进入第二步，不立即写入正式授权关系。

### 第二步：选择成员权限

弹窗包含：

```text
对成员发布
[已选择的成员、部门或角色]

成员权限
[权限下拉框]
```

规则：

- 点击“对成员发布”虚线区域，返回第一步重新选择。
- 返回第一步时保留原选择；再次确认后回到第二步。
- 已填写的自定义权限内容不能因返回选择对象而丢失。
- 最终点击“确定”后，把授权对象和权限一次性保存。
- 点击“取消”、关闭弹窗或中途退出，整个流程不生效。
- 保存期间主按钮进入加载状态，防止重复提交。
- 保存失败时保留当前选择与配置，并显示具体原因。

### 权限下拉框

按以下结构显示：

```text
已有自定义权限组
  [已有自定义权限组名称]

系统预置权限
  仅添加数据
  添加并管理本人数据
  添加并查看全部数据
  管理全部数据
  查看全部数据

＋新建自定义权限
```

- 已有自定义权限组是可选择项，不是编辑按钮。
- 选择已有组后，把对象加入该组；已有卡片时追加成员，不重复建组。
- 同一对象不得在同一权限组中重复授权。
- 允许选择一个尚未授予任何能力的已有自定义组，但保存前提示加入后仍无法访问数据。
- “＋新建自定义权限”创建独立权限组，并进入完整权限编辑界面。

## 6. 系统预置权限组

系统固定五种内部类型：

| 显示名称 | 内部类型 |
|---|---|
| 仅添加数据 | `ADD_ONLY` |
| 添加并管理本人数据 | `ADD_MANAGE_OWN` |
| 添加并查看全部数据 | `ADD_VIEW_ALL` |
| 管理全部数据 | `MANAGE_ALL` |
| 查看全部数据 | `VIEW_ALL` |

共同规则：

- 只允许修改 `display_name`。
- 禁止修改 `group_type`、固定说明、操作权限、字段权限和数据权限。
- 前端用灰色禁用控件展示只读权限；后端必须拒绝或忽略越权修改，不能只依赖前端禁用。
- 修改显示名称必须写审计日志，且不改变内部类型或实际能力。

### 6.1 固定操作权限矩阵

| 操作 | 仅添加 | 添加并管理本人 | 添加并查看全部 | 管理全部 | 查看全部 |
|---|:---:|:---:|:---:|:---:|:---:|
| 查看 | 否 | 是 | 是 | 是 | 是 |
| 添加 | 是 | 是 | 是 | 是 | 否 |
| 复制 | 否 | 是 | 否 | 是 | 否 |
| 编辑 | 否 | 是 | 否 | 是 | 否 |
| 删除 | 否 | 是 | 否 | 是 | 否 |
| 批量打印 | 否 | 是 | 是 | 是 | 是 |
| 批量修改 | 否 | 是 | 否 | 是 | 否 |
| 导入 | 否 | 否 | 否 | 否 | 否 |
| 导出 | 否 | 是 | 否 | 是 | 否 |

“全选”根据矩阵显示全选、半选或未选，但在预置组内不可点击。

### 6.2 仅添加数据 `ADD_ONLY`

- 固定说明：`在此分组内的成员只可以填报数据`。
- 编辑弹窗左侧只显示“名称信息”，不显示操作、字段和数据权限标签。
- 成员可以打开新增表单、填写并提交数据。
- 成员不能进入数据管理页查看记录，也不能查看、复制、编辑、删除、导入、导出或批量修改数据。
- 新增表单的可填写性遵守表单字段自身定义；系统字段仍不可编辑。

### 6.3 添加并管理本人数据 `ADD_MANAGE_OWN`

- 固定说明：`在此分组内的成员可以添加并管理本人提交的数据`。
- 数据范围固定为 `创建人 = 当前用户`。
- 查看、复制、编辑、删除、批量修改、导出、搜索、筛选和汇总都只能作用于本人提交的数据。
- 复制本人记录后，新记录的创建人和更新人必须是当前登录用户。
- 批量操作必须逐条在后端验证数据范围。
- 全部字段可见；普通可编辑字段可编辑；自动编号、计算、表单只读和系统字段不可编辑。

### 6.4 添加并查看全部数据 `ADD_VIEW_ALL`

- 可以添加数据、查看当前租户当前表单的全部数据和使用预留的批量打印权限。
- 不能复制、编辑、删除、批量修改、导入或导出已有数据。
- 查看已有数据时全部字段可见且只读。
- 新增数据时仍按表单字段定义填写允许输入的字段。

### 6.5 管理全部数据 `MANAGE_ALL`

- 固定说明：`在此分组内的成员可以管理全部数据、填报数据，但不可以导入数据`。
- 数据范围固定为当前租户当前表单的全部数据。
- 拥有查看、添加、复制、编辑、删除、批量打印、批量修改和导出权限。
- 固定没有导入权限。
- 全部字段可见；普通可编辑字段可编辑；自动编号、计算、表单只读和系统字段不可编辑。

### 6.6 查看全部数据 `VIEW_ALL`

- 可以查看当前租户当前表单的全部数据，并拥有预留的批量打印权限。
- 不能添加、复制、编辑、删除、批量修改、导入或导出。
- 全部字段可见且全部只读。

### 6.7 批量打印的最终规则

- 保留操作权限中的“批量打印”项及上表中的固定勾选状态。
- 自定义权限编辑器也保留“批量打印”选项。
- 默认工具栏、选中数据后的工具栏和“批量操作”菜单均不显示打印入口。
- 当前它只是预留能力，不应通过隐藏路由、快捷键或直接调用形成可用入口。
- 未来开发打印功能时必须复用现有 `batch_print` 权限校验，不能默认向所有用户开放。

## 7. 自定义权限组

新建或编辑自定义权限组时，左侧固定包含：

1. 名称信息
2. 操作权限
3. 字段权限
4. 数据权限

### 7.1 名称信息

- 名称必填，在当前表单内不得重名。
- 描述选填。
- 名称和描述均允许修改。

### 7.2 操作权限

提供以下权限：

- 查看
- 添加
- 复制
- 编辑
- 删除
- 批量打印
- 批量修改
- 导入
- 导出

规则：

- 新建自定义权限默认只勾选“查看”。
- “全选”支持全选、半选和未选三种状态。
- 编辑、删除、复制、导出、批量修改依赖查看权限。
- 取消查看时同步取消依赖权限，或阻止保存并明确指出冲突。
- 是否显示操作入口必须同时受权限与当前产品能力控制；批量打印遵守预留规则。

### 7.3 字段权限

使用三列表格：

```text
字段 | 可见 | 可编辑
```

- 新建自定义权限时所有字段默认未勾选。
- 勾选“可编辑”时自动勾选“可见”。
- 取消“可见”时同步取消“可编辑”。
- 表单定义为只读、自动编号、计算或系统生成的字段不能勾选可编辑。
- 创建人、创建时间、更新人、更新时间可配置是否可见，但永远不能编辑。
- 支持字段搜索。
- “全选—可见”和“全选—可编辑”分别支持全选、半选和未选。
- 字段较多时列表内部滚动，表头固定。
- 必填业务字段保留必填标识，但字段权限不能绕过表单本身的只读约束。

### 7.4 数据权限

允许配置：

- “所有条件”或“任一条件”，在界面中显示为两个独立选项。
- 一条或多条 `字段 → 运算符 → 值` 条件。
- 添加和删除条件。

规则：

- 运算符和值编辑器必须根据字段类型变化。
- 文本、数字、日期、字典、成员、部门等字段使用各自合法运算符。
- 当前用户等动态值由后端解析，不信任客户端传入的用户 ID。
- 条件由后端编译成参数化安全查询，禁止接受客户端 SQL、表达式代码或任意字段名。
- 如果权限包含查看、编辑、删除、导出或批量操作，必须有明确且可验证的数据范围；界面中的“全部数据”也要转换为显式的受租户和表单限制的后端范围。

### 7.5 保存校验

保存前检查：

- 名称已填写且不重复。
- 至少选择一个操作权限。
- 选择查看时至少一个字段可见。
- 选择编辑时至少一个字段可编辑。
- 数据权限条件完整且类型合法。
- 授权成员、部门或角色不为空。
- 系统字段未被授予编辑权限。

校验失败时停留在对应标签，突出显示问题，不得创建半成品权限组。

## 8. 后端安全边界

### 8.1 每个请求的校验顺序

按以下顺序执行：

1. 验证登录身份、用户状态和租户。
2. 验证表单归属和权限组启用状态。
3. 汇总成员、部门和角色带来的有效权限。
4. 校验请求动作。
5. 应用数据范围。
6. 应用字段可见与可编辑规则。
7. 执行业务校验、并发校验和写入。
8. 写审计并发布经过裁剪的实时事件。

### 8.2 数据泄露防护

- 无查看权限的字段不得出现在 API JSON、WebSocket、导出、复制内容、审计详情、错误信息或统计结果中。
- 无编辑权限的字段写入必须被后端拒绝或按明确策略忽略，并返回可定位的字段错误。
- 只读控制不能依赖 disabled 样式、隐藏按钮或前端路由。
- 根据 ID 读取、批量修改、导出和删除时仍要重新应用数据范围，防止通过伪造 ID 越权。
- 所有查询必须包含租户边界；超级管理员能力也应通过明确的后端策略授予。
- 默认拒绝未知动作、未知字段、未知权限组类型和无匹配授权。

### 8.3 审计

下列行为必须记录操作人、时间、租户、表单、权限组、请求来源、请求 ID、变更前和变更后内容：

- 权限组新增、复制、改名、删除、启用和停用。
- 成员、部门和角色的新增或移除。
- 操作权限、字段权限和数据权限变更。
- 数据新增、修改、删除、批量修改、导入和导出。
- 预置权限组的越权修改尝试。

敏感或无查看权限的字段在审计展示中仍须脱敏或裁剪。

## 9. 建议的数据模型约束

复用现有模型时确保至少能表达：

- `permission_groups`：租户、表单、内部类型、显示名称、说明、是否预置、是否启用、排序、版本。
- `permission_group_subjects`：权限组、对象类型、对象稳定 ID；建立防重复唯一约束。
- `permission_group_operations`：自定义组的操作授权；预置组由服务端常量或受控种子定义。
- `permission_group_fields`：字段可见、可编辑，引用稳定 `field_key`。
- `permission_group_data_rules`：条件组、所有/任一、字段、运算符、类型化值。
- `audit_logs`：完整变更上下文与不可变时间线。

数据库约束必须阻止：

- 跨租户引用。
- 同一权限组重复添加同一授权对象。
- 同一表单自定义权限组重名。
- 预置内部类型在同一表单重复。
- 可编辑为真但可见为假。

不要让数据库中的可编辑 JSON 成为预置权限的唯一真相；预置矩阵必须由不可随意修改的服务端规则约束。

## 10. 接口行为

- 读取预置权限组时返回可展示的权限快照和 `readOnly` 标识。
- 更新预置权限组时只接受 `display_name`；携带其他受保护字段时返回明确错误或完全忽略，但全系统采用一致策略。
- 添加成员两步流程在最终确定前只保存在前端草稿状态；最终提交使用一个事务性命令。
- 批量接口逐条做租户、数据范围、字段和版本校验，返回逐项结果。
- 导入采用“上传/解析 → 预览 → 确认写入”，并使用幂等键；预置权限组当前全部禁止导入。
- 导出内容按当前用户的数据范围和字段可见权限裁剪。

## 11. 最低验收测试

至少覆盖以下场景：

1. 五个预置权限的操作矩阵、字段状态和数据范围与本文完全一致。
2. 改名后内部权限不变；尝试修改预置权限其他字段被后端阻止。
3. `ADD_MANAGE_OWN` 用户无法通过列表、详情、批量接口、导出或伪造 ID 访问他人数据。
4. `ADD_VIEW_ALL` 能新增和查看全部数据，但不能修改已有数据。
5. `VIEW_ALL` 只能查看；`ADD_ONLY` 提交后不能进入数据管理页查看记录。
6. 系统字段无法通过任何入口修改。
7. 成员、部门和角色权限正确叠加；停用一个组不影响其他组贡献的权限。
8. 用户离职、停用或移出租户后立即失去有效权限，历史审计仍可追溯。
9. 返回第一步重新选择授权对象时，原选择和自定义权限草稿不丢失；取消后不落库。
10. 权限变更后缓存立即失效，实时广播不泄露无权字段。
11. 三处工具栏都没有批量打印入口，但权限定义仍保留。
12. 并发更新产生可理解的冲突响应，不静默覆盖。

## 12. 禁止事项

- 不得根据中文显示名称判断权限组类型。
- 不得把用户名或姓名当作授权主键。
- 不得让前端决定“当前用户”或租户范围。
- 不得仅靠灰色控件、隐藏按钮或路由守卫实现安全。
- 不得把无权字段先返回前端再隐藏。
- 不得给五个预置权限增加导入能力。
- 不得在任何工具栏或批量菜单中增加批量打印入口。
- 不得把 `null`、空字符串和 0 当成同一个值。
- 不得为了局部功能破坏现有主计划双层表头、字段键、审计、乐观锁或实时协同机制。
