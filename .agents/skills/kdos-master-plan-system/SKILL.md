# KDOS 主计划系统

本 Skill 是主计划业务行为的项目级入口。实现或调查计划生成、同步、生命周期、工序及报工时，先读本文件和 [事业部基础计划业务规范](../../../docskill/主计划/订单执行/事业部基础计划.md)。生产基线 `5f90e589f845defe2c02591072f0d285a3981e73` 固化了本 Skill 的周计划准入规则。

一般表格权限、租户、审计、API 和数据安全仍遵守 `.agents/skills/kdos-form-platform/SKILL.md`。涉及运行任务、outbox、调度或故障恢复时同时遵守 `.agents/skills/kdos-task-orchestration/SKILL.md` 和 `docs/operations/TASK_REGISTRY.md`。`docs/operations/MPS_UPSTREAM_DOWNSTREAM_LINKAGE_DESIGN.md` 含较早的调查和方案快照；遇到其中与本 Skill 冲突的 ACTIVE、来源确认或历史恢复门槛，以本 Skill 和现行 docskill 为准，不得从历史快照恢复旧准入规则。

## 计划层级与来源

| 计划/执行对象 | 直接数据来源 | 规则 |
| --- | --- | --- |
| 集团主计划 | 订单分配表 | 订单分配是需求依据。 |
| 事业部月度计划 | 订单分配表 | 订单分配的承接事业部决定归属；分配审核状态不构成额外准入门槛。 |
| 事业部基础计划 | 事业部月度计划 | 基础计划是事业部周计划的直接来源。出货计划不是基础计划生成前置来源。 |
| 事业部周计划 | 事业部基础计划 | 以基础计划当前有效业务数据和下述准入规则生成。 |
| 周计划工序明细 | 周计划及该事业部有效默认工序配置 | 使用事业部默认路线；不得用品项专属工艺路线替换该默认路线。 |
| 报工系统 | 有效周计划工序任务 | 待报工任务来自工序任务；实际报工记录只能由真实报工提交产生。 |

ERP 原始订单行 ID 不是任何层级计划生成的必要关联条件。历史来源外键用于追溯、审计和维护，不是周计划生成前置条件；KDOS 分配审核状态也不是月度、基础或周计划的额外准入条件。

## 周计划生成准入

事业部基础计划是周计划唯一直接业务来源。首次生成应以该基础计划的有效性、字段、数量、真实业务状态及工序配置判定。当前唯一的五项周计划必填字段由代码共享定义 `weeklyAdmissionRequiredFields` 提供：

1. 最迟客户交期 `latestCustomerDueDate`。
2. 最迟评审交期 `latestReviewDueDate`。
3. 产品属性 `productAttribute`。
4. 表面性质 `surfaceNature`。
5. 生产方式 `manufacturingMethod`。

空字符串与 `NULL` 都视为缺失。不得未经用户确认增加必填字段或准入限制。计划数量遵守现行数值规则及数据库约束；不得把 ERP 入库数量或报工数量当成计划数量。

业务/配置阻塞仅限真实情况：基础计划真实暂停、取消、失效或业务状态无效；真实对应月度业务需求暂停/取消；数量违反现行规则；需要内部工序但缺少该事业部有效默认工序路线；重复计划或与既有生产执行事实发生冲突。对已有稳定父关系的真实冲突、租户/事业部归属、权限和审计规则继续校验；不得把缺少历史父关联等同于冲突。

`ACTIVE` 与 `LEGACY_RETAINED` 均可继续进行周计划生成判定。`LEGACY_RETAINED` 或来源待核实只代表历史追溯状态，不代表业务暂停或取消。基础计划历史来源未核实、缺少历史月度关联、月度历史来源未确认或不是 `ACTIVE`、缺少 ERP 原始订单行 ID、订单分配未审核、生命周期写入开关关闭、仅有 ERP 入库事实、或历史 outbox 为 SUCCESS/FAILED/BLOCKED/重试耗尽，都不得单独阻止首次周计划及安全的首次工序初始化。

不得通过隐藏的 Application 校验、SQL 谓词、生命周期守卫、触发器、恢复前置任务或间接来源核验重新引入上述限制。来源关联仍可用于追溯、审计及独立数据维护；来源恢复机制是否成功不能决定周计划准入。

## 自动同步、重试与幂等

- 使用现有业务事件、reconciliation/outbox、`base-to-weekly` 自动扫描和已登记的 30 分钟调度；不得新建重复定时任务。运行调度规则时同时阅读 `kdos-task-orchestration` 与任务台账。
- 事件、自动扫描和手工同步共用同一业务准入及生成服务。自动扫描必须主动发现当前符合条件但没有周计划的基础计划，不能只消费历史 outbox。
- 旧 outbox 的任何状态不能永久排除当前符合条件的计划。重新判断当前业务数据；可重试的当前失败要保留真实原因并按现有安全规则重试。
- 单条计划的真实阻塞或失败要被隔离并准确记录，不能回滚或跳过同一事业部/租户的其他有效计划。
- 一条基础计划最多一条有效周计划，一周计划＋工序编码最多一条工序任务。重复运行必须幂等，不覆盖实际报工、已锁定路线或其他执行事实。
- 周计划状态、缺少项和提示必须复用后端当前准入逻辑，准确区分字段缺失、缺少默认路线、等待自动同步、已进入周计划、真实业务阻塞和当前同步失败。不得再显示“基础计划历史来源待核实”作为生成阻塞。较旧失败仅作为审计留存，不得覆盖后续成功的当前状态；已正常生成不能同时显示当前生成失败，除非存在独立、尚未解决的新失败。

## 工序与生产事实

- 新周计划按对应事业部已启用的有效默认工序配置初始化任务。没有有效默认配置时明确阻塞，不回退到通用十工序；工序标准顺序唯一来自 `@tracker/shared`。
- `自制` 生成内部工序任务；`自制+外协` 生成内部工序及外协执行任务；`中心外购`、`外协` 按现有规则不生成内部工序任务。
- 仅有 ERP 入库记录不是 KDOS 工序报工，也不阻止安全地生成缺失周计划或首次初始化工序任务。不得创建虚假/零数量报工来代替工序任务。
- 已有周计划、任务快照、锁定路线、报工、入库、审计及其他执行事实必须保留。普通修复不得重复生成、删除/覆盖事实、修改数量/事业部/默认路线，或为消除提示而重新激活真实暂停/取消计划。
- 首次补建工序只允许在该周计划此前没有任何工序快照、报工、持久路线锁或确认空路线审计时执行；不得覆盖已有或部分路线，不得重启人工停用任务。

## 故障排查和验收

涉及主计划生成、同步、生命周期、工序任务和报工时，独立检查实际业务链：订单分配表 → 月度计划 → 基础计划 → 周计划 → 工序任务 → 报工系统（集团计划同时由分配投影）。缺失检查必须从实际业务数据出发，不得只复用自动同步器的候选筛选，否则被错误排除的记录会再次漏检。

以下结果均不能单独作为业务验收依据：outbox 为 SUCCESS、待处理事件为 0、ACTIVE 状态异常为 0、自动任务成功、API 健康、单元测试通过。验收须证明实际计划和应有工序任务存在、业务状态正确、满足报工条件的任务可由报工 Query Service 查询。共性故障覆盖全部受影响事业部，修复根因并通过正式 Application Service/既有同步机制安全恢复同类数据，不能只补用户反馈的一单，也不能直接插入派生业务行。扫描保持有界批次、逐条隔离、keyset/索引友好查询及合理 statement timeout。

开发验收必须覆盖下列 13 项。使用隔离数据库和真实 `runDue`/事件入口验证自动链路；不能以仅调用手工同步代替自动回归，不能在生产创建合成业务数据。维护验收文档本身不代表已执行这些业务测试。

| 序号 | 回归场景 | 必须观察的结果 |
| --- | --- | --- |
| 1 | 历史来源未确认，业务条件齐全 | 自动生成周计划，不要求手工核实来源。 |
| 2 | 缺少历史月度计划外键 | 正常生成；保留原追溯缺口，不强制补链。 |
| 3 | 基础计划为 `LEGACY_RETAINED`，或历史月度非 `ACTIVE`/来源未确认 | 不单独阻止生成；真实暂停/取消仍按第 11 项保护。 |
| 4 | 通用生命周期写入开关关闭 | 正常生成，不需要开启该开关或先恢复 ACTIVE。 |
| 5 | 已存在 ERP 入库事实 | 安全生成缺失周计划和首次工序任务，入库事实不变。 |
| 6 | 补齐五项必填字段 | 自动入口发现并生成，无需点击“同步到周计划”。 |
| 7 | 自动、事件与手工同步 | 共用准入及生成逻辑；结果一致，缺路线不回退通用工序。 |
| 8 | 历史同步失败、outbox 已成功/失败/耗尽重试 | 当前合格计划仍会被扫描发现；旧事件不永久排除。 |
| 9 | 单条计划异常/真实阻塞 | 同事业部、同租户其他有效记录继续同步，结果逐条可追溯。 |
| 10 | 重复/并发执行同步 | 不重复周计划或工序任务；既有身份和执行事实不变。 |
| 11 | 真实暂停、取消、失效、重复/归属或执行冲突 | 继续正确保护；已有报工、锁定路线及人工停用任务不被覆盖或复活。 |
| 12 | 生成成功后存在历史错误 | 显示已进入周计划；失效旧错误仅留审计，独立未解决的新失败如实显示。 |
| 13 | 有效周计划且生产方式需要内部工序 | 应有对应事业部默认路线工序任务；满足报工条件时可从报工系统查询。外购/外协不误造内部任务。 |

[历史故障案例与根因](references/regression-cases.md)记录五个指定案例及应保持的行为；排查同类问题时阅读。案例编号只用于追溯和回归样本定位，不得在业务代码、候选筛选或生成规则中硬编码订单号/品号。
