# 表单页面布局设计规范

在 KDOS 内新建或调整业务表单页面时，先读取本 Skill，并同时遵守根 `AGENTS.md`、`.agents/skills/kdos-form-platform/SKILL.md` 及适用的业务文档。该 Skill 只规范页面组织和视觉布局，不替代字段、业务规则、权限或数据生命周期定义。

## 布局选择

- 根据表单容器实际可用宽度、字段长度和录入顺序选一列、两列或四列。宽屏多字段表单可采用 `repeat(4, minmax(0, 1fr))`；中等宽度降为两列，窄宽度降为一列。优先使用容器查询；断点需按控件最小可读宽度验证。四列是宽屏建议，不是所有表单的强制要求。
- 用业务分组组织字段，而非直接照抄数据库顺序。短文本、数字、成员/部门选择通常占一列；长文本跨整行；附件或并列业务区可各占两列；关联子表或明细表通常全宽。
- 通过显式布局顺序和跨列规则表达业务关系。字段因权限不可见时不得保留空白可写控件；布局变化不得修改字段契约或访问权限。

## 表单控件与分组

- 新增、编辑、查看模式应有清楚的标题和业务分组。标签统一置于输入控件上方；同类输入保持一致的高度、边框、圆角、间距与错误提示。必填标识、帮助文字和字段校验错误应清晰且贴近对应字段。
- 只读、禁用、必填、校验失败、上传成功、提交中、提交失败应有可辨识状态。只读字段仍按字段权限显示，不以视觉禁用替代服务端权限验证。
- 保留项目既有表单、输入、选择、成员/部门、附件和表格组件以及 KDOS 主题。不要为单页引入另一套表单框架或重复实现公共控件。
- 附件区应与普通字段区区分，说明必要的模板或上传要求，并保留真实模板、文件校验、文件列表和移除能力。多个附件字段可并排，窄容器下应自然堆叠。
- 内嵌子表和关联子表应维持各自数据结构、保存事务、ID、权限及版本语义。可用横向表格展示重复的同类字段；窄屏时允许明细容器内部横向滚动，不使弹窗整体横向溢出。增删操作遵循对应项目 Skill 与原有权限策略。

## 弹窗与滚动

- 弹窗水平居中，最大宽度按字段密度确定（宽屏业务录入可参考约1320px），且始终不超出视口；最大高度不超过视口减去安全留白。
- 标题和操作栏保持可见，只让表单主体纵向滚动。弹窗可采用白底、浅边框、适度圆角和轻阴影，优先使用项目现有视觉语言。
- 底部按钮固定在弹窗操作区，保持取消与主要提交操作的清晰层级；加载时防重复提交，窄屏按钮不能被遮挡或覆盖字段。
- 页面级容器与表格宽度不得因扩大表单弹窗而改变。使用局部类名或隔离样式，避免影响其他业务表单和报表。

## 业务边界与可访问性

- 布局调整必须保持字段、默认值、联动、校验、附件处理、提交和回填行为；除需求明确要求外，不改 API、数据库、业务编号、审计或业务规则。
- 保留字段/资源/记录权限和服务端校验。隐藏按钮、只读样式和前端校验都不能作为授权边界。
- 确保键盘可操作、焦点可见、错误能被识别；弹窗打开、关闭及未保存数据处理遵循项目现有模式。

## 交付与文档

- 编码前检查实际表单、公共组件、样式作用域和字段/权限定义，并先在相应 `docskill/` 文档写清布局设计。同步说明分组与顺序、列数与跨列、附件和子表、滚动/操作区以及既有业务行为的保持边界。
- 修改后按影响范围验证宽屏、中屏、窄屏布局，弹窗滚动与固定操作区，以及新增/编辑、联动、校验、附件、子表增删和权限。优先复用仓库现有测试；有浏览器环境时做实际页面检查。
- 在同一业务 docskill 的修改记录中说明布局变化和日期。若本 Skill 的通用规范变化，也更新项目 Skill 入口或相关引用，避免出现未被发现的孤立规则。
- 本规范维护页面布局；字段完整定义、权限矩阵、导入导出、删除、审计等仍以 `kdos-form-platform` 和业务 docskill 为准。

## 选择框长文本补充（2026-11-21）

关联/部门/成员下拉应有足够列宽，控件占满单元格；长路径省略后提供hover及键盘focus完整文字提示，选项与已选单值/多值均适用。Tooltip/下拉通过既有portal挂到安全容器避免被弹窗overflow裁剪，明细允许内部横向滚动；局部样式不得让整页横向溢出或影响其它表单。
