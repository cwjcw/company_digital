# 财务中心 · 鼎捷 E10 销售订单月度数据与统计大屏

状态：**需求与技术设计，尚未实施、部署或验收**。记录日期：2026-10-13。输入依据：用户提供的《财务模板.xlsx》，包含 `系统导出`（34列订单品项）、`月度数据`（9列订单汇总）、`统计大屏`（四类强制统计）。**不得将用户真实业务 Excel、业务金额明细或登录凭据提交到公开仓库。**

## 1. 目标和范围

在**既有财务中心**扩展“销售订单统计”，不重建财务中心、客户对应表、ERP 同步引擎、权限框架或大屏图表公共组件。

第一期由人工在鼎捷 E10 导出“系统导出”格式的 Excel → KDOS 上传、预检、导入 → 生成“月度数据”订单级汇总 → 统计大屏。只有在经过源数据字段、权限与金额验证之后，才考虑第二期 E10 只读 API/SQL 自动采集以及 n8n 调度；**本期不增加、修改、停用任何 n8n/systemd 定时任务**，遵守 `.agents/skills/kdos-task-orchestration/SKILL.md`。

拟定导航（尊重既有权限菜单与统一单一导航）：
- 财务中心
  - 基础数据 → 客户对应表（保留原页面及接口）
  - 销售订单统计 → 系统导出（数据导入/批次记录/原始明细）
  - 销售订单统计 → 月度数据（订单级查询与导出）
  - 销售订单统计 → 统计大屏（BI展示）

## 2. 输入字段和数据粒度

### 2.1 源 Sheet：系统导出（34列，**订单品项级**）

列顺序必须兼容模板：

| 序号 | 字段 | 序号 | 字段 |
| --- | --- | --- | --- |
| 1 | 单据类型 | 18 | 计价数量 |
| 2 | 业务员姓名 | 19 | 计价单位 |
| 3 | 客户编号 | 20 | 已交业务数量 |
| 4 | 年月 | 21 | 已交计价数量 |
| 5 | 订单日期 | 22 | 结束码 |
| 6 | 单号 | 23 | 已结算计价数量 |
| 7 | 销售部门名称 | 24 | 单价 |
| 8 | 预交货日 | 25 | 金额 |
| 9 | 币种 | 26 | 税种名称 |
| 10 | 汇率 | 27 | 税率 |
| 11 | 序号 | 28 | 原币未税金额 |
| 12 | 品号 | 29 | 原币税额 |
| 13 | 品名 | 30 | 本币未税金额 |
| 14 | 业务数量 | 31 | 本币税额 |
| 15 | 客户单号 | 32 | 结算状态 |
| 16 | 备注-业务 | 33 | 审核 |
| 17 | 含税 | 34 | 本币合计金额 |

- 识别指定 Sheet（允许工作簿含其他 Sheet），不依赖用户提供的统计结果；保留原始导出全字段、原行号、导入批次。
- 既有平台**加密容器检测必须先于解析**；兼容实际 E10/WPS 导出，首先使用项目既有 Excel 解析能力，不为单一场景引入重复解析框架。
- Excel 数值日期/文本日期兼容；`年月` 规范化成 `YYYY-MM`，`订单日期` 和 `预交货日` 规范化成日期。解析失败必须报行号和字段，禁止静默猜测。
- 基础金额字段采用 `numeric/decimal` 精确处理；优先使用原 Excel `本币合计金额` 的有效数值或可靠公式缓存，校验其与 `本币未税金额+本币税额` 的差异（容差仅允许合理的四舍五入）；任何缺失/明显差异进入异常，不可无提示选另一值。**禁止用原币金额、单价或重复汇率换算代替本币含税金额**。
- 账套与源报告范围必须明示，默认 `E10`，不得把 T+ 数据混入本财务报表。单据类型、审核、结束码和结算状态按源值留存，**不根据“已结束”或“已结算”默认筛选**，除非业务后续明确口径。

### 2.2 派生 Sheet：月度数据（9列，**销售订单级**）

表头与顺序固定：

`年月｜客户编号｜单号｜订单日期｜预交货日｜本币总金额｜客户单号｜事业部划分｜国内外划分`

转换规则：
1. 源明细按 `tenant + E10来源 + 单号` 分组为一条销售订单（如果 E10 编码证明不同账套共享单号，则来源账套亦纳入唯一键；不能跨来源误合并）。同一个单号多个“品项/序号”**要相加，不得只取首行或把整单重复计数**。
2. `本币总金额 = SUM(对应有效品项.本币合计金额)`，精确到分。Excel 包含原始 `本币合计金额 = 本币未税金额+本币税额` 逻辑；金额单位**人民币元（含税订单额）**。
3. 同一订单的客户编号、年月、订单日期、预交货日、客户单号如存在非空互相冲突，应输出异常并阻止该订单无提示自动归并；不可任取首行。
4. `年月` 优先保持 E10 导出的业务年月；与订单日期月份不同，标出差异供复核，不擅自更改业务周期。所有按年/月统计必须使用同一规范化后的“年月”字段。
5. `事业部划分`、`国内外划分` **只能**以 `tenant_id + 完整客户编号` 精确 JOIN 已有 `finance_customer_mappings`：分别读取 `department_category`、`sales_channel`。不能使用 ERP “销售部门名称”、订单号前缀、客户编号前缀或 PMC 事业部映射进行推断。
6. 财务字典来源 `packages/contracts/src/finance.ts`：`业务一部/业务二部/业务三部/业务四部` 和 `内销/外销`。数据存储/规则用 `内销`，如按模板展示 `国内`，仅做受控展示映射（`内销 → 国内`），不能保存混乱的两种内部枚举。
7. 未匹配客户或两个分类任一为空：展示“待分类”并提供“未分类客户数/订单数/金额”，金额仍计入**订单总额**，但不强行归到某事业部或内外销；财务人员应去已有客户对应表补全，禁止本次导入自动改写客户分类。推荐报表口径为**当前财务客户分类**，映射修正时历史分析随之更新并标识“按当前分类”；若需要财务关账锁定快照另提专项方案。
8. 允许金额为0的订单记录；负数、重复序号、异常金额、跨导出重叠、同一订单不一致须进入复核，禁止静默删除。

## 3. 批次导入、幂等与安全

- 上传页面提供模板/说明、文件预检、导入确认、处理结果（品项行数、订单数、总额、映射成功/待分类数量、日期/金额/订单冲突）、按批次回看与错误 Excel 下载。**不得直接一上传就覆盖已存在业务数据**。
- 重复导入相同文件/同一订单行不得重复累计。建议原始报表按 SHA-256 标识批次，品项使用来源账套+单号+行序号等稳定业务键进行幂等；遇到同键内容变更采用可审计的替换/版本策略而非追加重复累计。
- **导出范围可能只是某一月份或部分订单**：不能把“这次没出现在文件的旧订单”判作取消。默认增量导入/upsert；只有经用户明确选择并预览差异的完整月份替换才允许失效缺失记录，并保留可恢复旧版本。
- 使用上传文件存储和权限隔离机制；结构化原始财务数据和导入批次建议位于财务专用 schema/表，导入与订单级汇总处于统一受控事务。必须先调查既有 `erp_staging_*` 与 `sales_orders` 是否适合复用；财务报表可有带来源批次的派生投影，但**禁止制造第二套与正式 ERP 订单表争写的“权威销售订单表”**。
- 业务数据只能经过 Finance Application Service 和权限检查写入，不允许 Excel 前端/n8n 直连 PostgreSQL 改表；保存审计与批次错误。
- 多租户隔离、财务模块 read/import/export 权限、字段与 data scope、管理员与普通财务人员权限均遵循 `AGENTS.md` 及 `.agents/skills/kdos-form-platform/SKILL.md`。原财务客户映射、PMC映射、原订单和主计划数据必须保持不变。
- 性能基线：分页/筛选/导出均从服务器完成；订单明细大表不得一次全部返回前端。规模大时使用带索引的标准汇总查询或可维护的物化/缓存，不在浏览器计算全年汇总。

## 4. 统计大屏（模板要求必须全部落地）

数据口径统一为选定时间范围、租户/权限范围内的**本币含税订单金额**，不是到账金额、开票金额或会计营业收入；数据从同一订单级来源聚合，不能人工维护四套统计数据。

### 必须实现的4组

1. **国内/外销**：金额（元或万元）、所选年度占比、合计；内销前端可称“国内”，必须有“待分类”可见项，不得金额消失。
2. **事业部**：业务一部、二部、三部、四部金额与占比，全年合计；没有订单也可显示0，不得仅支持前三个部门。
3. **客户年度金额排名**：按完整客户编号汇总、金额降序、占比、TOP 10/20及明细列表；保留查询全部客户和导出能力，不因后缀相似而合并。
4. **1—12月趋势**：每月订单额（元、万元）与合计；空月显示0，趋势图+表格统一后台指标。

### 建议追加（需先满足上述四组）

- KPI：累计接单额、当月接单额、订单数、客单金额、同比/环比（缺少完整比较期时展示“无数据”，不算0增长）。
- 事业部 × 国内/外销 交叉金额矩阵，可点击下钻订单明细。
- TOP客户集中度、客户金额帕累托、销售人员贡献（必须获得相应字段权限）。
- 财务数据质量提示：未映射/空分类客户及金额、ERP业务月份与订单日期不一致、零金额订单、金额校验失败、最近导入时间及数据覆盖区间。
- 预交货日即将到期订单可作为**合同约定交期提示**，但不能只凭预交货日推断实际交货率/逾期交货：需要正式履约数据才展示交付指标。

筛选统一：年度（必选）、月份或自定义区间、事业部、国内/外销、客户编号、业务员；默认沿用 KDOS Dashboard 日期选择规范，在「按年」页面明示所选年度。图表下钻后，明细与导出继承完全相同的权限和过滤条件。展示“元/万元”切换只改变表现形式、**不改变源金额**。

## 5. 对账与数据质量（关键验收）

- 同一业务范围、相同筛选条件：`订单级月度总额 = 按月份求和 = 按客户编号求和 = 按事业部含待分类求和 = 内/外销含待分类求和`，所有金额按 Decimal 处理并允许合理的分级舍入误差。
- 原始品项行数与订单条数分开展示；真实订单以唯一业务键计数。指标旁明确“销售订单含税金额”。
- 用户提供工作簿的三个 Sheet 属于**不同展示数据集**，原始样例不应拿来做跨 Sheet 同数验收。模板统计页的年合计与月度合计本身存在差异，应将其视为产品需避免的对账问题，而不是模板结果的标准答案。
- 自动化测试至少：一单多行求和、不同单号不合并、0金额、中文/Excel日期、错列/缺字段、金额异常、客户精准匹配（包含带后缀客户）、待分类不漏金额、客户分类后来改变、重复批次/部分导入、月份与订单日期冲突、跨租户/无权限、两个统计维度合计一致、元/万元切换。
- 验收需用用户真实 E10 导出**在授权生产环境本地**测试；用户 Excel 不进入公开 Git，公共测试只使用人工合成 fixtures。若缺少真实样本，不得宣称生产导出格式已验收。

## 6. 分阶段实施与交付

- **Phase 1A — 只读调查**：检查 finance 现有路由/数据结构/权限、导入加密检测、现有 ERP staging / canonical 业务表、KdosDataTable、ECharts 共享框架；输出最终复用点与 schema/接口最小变更清单。未经确认不得改变其它模块。
- **Phase 1B — 导入与月度数据**：数据库 migration / Finance Application Command、文件预检、批次幂等、订单级汇总、映射联动、过滤分页导出、权限与审计；使用隔离合成样本回归。
- **Phase 1C — 统计大屏**：模板四组强制图表及数据核对、筛选下钻、导出，再添加可选 KPI 与质量提示。真实 UI/服务端数字对账、性能和权限验收。
- **Phase 2（另行授权） — ERP 自动采集**：仅在用户明确要求时，验证 E10 SQL/API 与模板字段等价性，并依照项目调度 Skill 决定 n8n；不得与现有 ERP staging 流程争写或产生第二份不一致账本。
