## 最新变更：日期时间显示到秒（2026-10-14）

- 本财务模块所有可见**日期时间**统一为用户指定的 `YYYY-MM-DD HH:MM:SS`（如 `2026-11-10 08:30:00`），覆盖「系统导出」「月度数据」「统计大屏」及刷新批次/日志、查询下钻、Excel 导出；字段名保持原中文不变。业务 `年月` 仍是 `YYYY-MM`，筛选日期输入仍可使用 `YYYY-MM-DD`。
- 当前已查明：`packages/contracts/src/finance-order-fields.json` 的 `订单日期`、`预交货日` SQL 表达式使用 `CONVERT(char(10),...,23)`，`apps/api/src/modules/finance/finance-orders.application.service.ts` 对日期校验仅允许 `YYYY-MM-DD`，`1722920089000-FinanceE10Analytics.ts` 的订单/交期视图转换为 `::date`，`FinanceOrders.tsx` 读取批次时间有只显示到分钟的地方；这些均需系统修复，**不能只在 UI 将截断的日期补 `00:00:00`**。
- 先只读核实 E10 的 `h.ORDER_DATE` / `d.PLAN_DELIVERY_DATE` 类型与真实有效时间。源若有小时分秒，应保存/传递到秒；若源只有日期精度，可格式化展示 `00:00:00`，但验收说明时间部分为格式补齐而非源业务时刻，禁止把日期型字段伪造成有实际精度的时间。
- 应保证 NDJSON Reader、API 校验、PostgreSQL 读模型/视图、日期筛选/排序、前端显示、Excel 导出/打印均能兼容有时分秒的数据，并保持业务本地时区 `Asia/Shanghai` 语义。不要把无时区的 SQL Server 日期错误按 UTC 转换。历史数据库 migration 禁止回写，新增前向 migration 做兼容改造。需要受控 E10 重读/刷新旧数据以获取真实时间。
- 原交期汇总规则仍是 `MIN(同单所有品项非空有效预交货日期时间)`，比较到秒；必须纠正此前“冲突254张留空”的实现/报表提示，不能因为日期不同导致置空。财务统计金额、订单数、客户映射与现有定时任务不能受影响。
- 验收增加：同日不同时分秒的 MIN、跨日 MIN、空时间、有秒值、真实 E10 时区语义、API/原始明细/月度表/大屏日志/Excel显示格式一致、2025-01-01 边界，以及前后金额和订单数保持一致。Day.js 格式串必须使用 `YYYY-MM-DD HH:mm:ss`（小写 `mm` 为分钟，`ss` 为秒），不能直接使用用户约定中大写 `MM:SS` 作为函数参数。
