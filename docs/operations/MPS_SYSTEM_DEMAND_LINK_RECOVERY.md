# KDOS 需求来源关联恢复规范

本文说明月度需求、订单分配、基础计划和周计划之间的稳定身份关联，以及如何安全处理历史归档来源阻断。本文不包含生产订单、业务行 ID、请求记录或生产快照。

## 1. 关联规则

- 以月度需求稳定 ID 作为需求根；基础计划及周计划保留各自稳定 ID，并通过正式外键关联。
- 正常新建数据只自动关联本次新行。历史空关联或归档来源不得按订单号、品项或数量模糊回填。
- 只有租户、订单、品项、事业部和客户身份一致，且唯一有效来源及唯一目标均可证明时，才允许使用受审计的正式 Application Command 恢复身份关联。
- 人工独立计划、真实拆分、多候选、入库、外协、报工、排产或其他执行事实出现时，停止自动重挂，保留原记录及关系并报告具体冲突类别。
- 数量投影只更新自动维护字段；实际入库、报工、工序任务、人工字段和历史审计不得被重置。集团汇总按整张订单的有效需求重新计算。

## 2. 受控恢复

1. 使用只读查询确认当前有效来源、来源版本、归档来源、计划父关系、人工维护标记及全部执行事实。
2. 在隔离 PostgreSQL 中验证唯一可恢复场景、真实冲突保护、幂等、并发写入和下游投影。
3. 发布已验收的最小 API 版本。生产数据恢复须通过正式身份认证和权限检查的 Application Command，并提供期望版本及明确原因。
4. 命令在事务内锁定目标、复核租户和业务身份、写入审计与定向 Outbox；不得直接改表、伪造 actor、覆盖旧失败事件或关闭保护。
5. 通过持久 Outbox 逐层处理月度、基础、周计划和集团投影。按业务键隔离故障；重试有上限，真实冲突继续 BLOCKED。
6. 每层完成后只读核对来源关系、需求/排产/完成/剩余数量、任务及执行事实，并确认审计与 Outbox 状态。

## 3. 数据库及发布边界

- 按发布 runbook 先备份并校验摘要；只执行该候选明确列出的迁移。本恢复路径本身不要求通用 Migration。
- 不运行全部待执行 Migration，不清理历史 Outbox，不批量回填其他历史行。
- 生产验证必须核对 API 镜像完整 SHA、健康状态、Web 版本及原调度配置；源码构建或 GitHub 推送不能代替生产验收。
- 回滚采用此前已验收的应用镜像；不得恢复整库覆盖部署后的新业务数据。
