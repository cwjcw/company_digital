# PMC order allocation import and notifications

The ERP `分配` workbook can be uploaded directly under PMC → 主计划系统 → 数据准备 → 订单分配表. Header whitespace and line breaks are normalized; columns can move. The encrypted-file guard runs before Excel parsing. The server's explicit nonmoney field allowlist governs parsing, comparisons, audit snapshots, outbox snapshots and recipient attachments. 含税单价、含税金额、原币单价、采购金额 are never read or written.

Allocation identity is the stable tenant-scoped record UUID. Every newly uploaded preview has a new UUIDv7 import batch; confirmation inserts every valid physical source row, preserving duplicate order/item/sequence values and identical lines. Only repeated confirmation of that same preview/batch is idempotent. File SHA is a repeated-upload warning, never a cross-batch deduplication key. Old export IDs/versions are ignored with a preview notice; page edits still use stable ID plus optimistic version. Source batch, worksheet, row, time and actor are server-maintained readonly context.

When 未分配数量 exists in the input headers, it is the sole source of KDOS 已分配数量; the ERP 已分配数量 column is ignored. KDOS templates containing only 已分配数量 use that value. No subtraction or sum is used. Numeric formulas require saved valid caches; missing/error caches or blank selected quantities block confirmation with source cell coordinates. Templates/exports/events/attachments exclude the retired independent quantity field and all prohibited prices/money. Templates and current allocation exports omit overwrite identity columns; old exported identities remain safely ignored.

Migration 93 archives retired quantities and grants, repairs only proven unedited legacy-import rows, removes the old field and allocation business/sequence uniqueness, and creates tenant-scoped batch/row identities. It backfills the monthly plan's stable allocation-ID foreign key before dropping the old business-key reference; historical record/plan IDs and money remain intact. Conditional schema rollback refuses any append batch or duplicate business/sequence identity. Proven quantity corrections are retained on safe rollback. Rollback code must preserve the manual-source and suspended-downstream policies.

Supplier names resolve exactly through the tenant's enabled vendor mappings. The five default mappings and five recipient units are seeded idempotently without replacing administrator settings. Explicit file divisions are retained when supplier mapping conflicts; the explicit override option requires field/update permission and a new preview before confirmation. Allocation data is maintained exclusively through authorized manual operations and confirmed Excel imports. ERP projection does not create, modify or delete allocation rows, including historical ERP-origin rows. Per the latest user instruction, downstream plan-projections are suspended; allocation/customer-map writes do not enqueue them, all run entrypoints skip, and pending work is retained without consumption. The production plan-projections configuration is disabled through the audited API; unrelated job schedules remain in place.

Configuration lives only under PMC → 主计划系统 → 系统运维 → 订单分配通知配置. It requires a system or PMC administrator. Edits use versions and tenant-scoped audit. Employee IDs come from the existing KDOS directory; the directory has an explicit tenant field (existing employees belong to KAINAN), and live WeCom UserIds are resolved at delivery. Procurement is an existing organization value, not an additional division model. The top switch changes the canonical message rule itself. The rule starts disabled. Switching it on never sends changes that occurred while disabled.

`mps.order_allocation.batch_changed` / `ORDER_ALLOCATION_DYNAMIC` is registered in the existing message center. Create, edit, batch edit and import confirmation emit one immutable batch event for actual nonmoney changes within the business transaction. Unchanged writes and previews do not emit events. Unit recipients and all enabled exact full-name salesperson matches are combined by KDOS user ID. Old and new unit/salesperson identities receive transfers. Each recipient's rows are the union of their own scopes. Routing is frozen when deliveries are prepared; disabled/deleted/foreign users are revalidated before retries. Configuration errors are logged as failed, never sent; other valid recipients continue. An administrator retry of a routing failure reevaluates corrected configuration.

Each recipient receives a summary text and a real XLSX with 新增订单 / 变更订单 / 字段变更明细. Files contain only allowlisted fields, retain code zeros and exact decimals, use real date cells, freeze/filter headers and escape formula-like text. Files exceeding the WeCom limit split recursively without dropping rows. Immutable per-recipient parts are private PostgreSQL bytea attachments, covered by the existing database backup; they are never public static files. The internal download requires the worker's token, tenant and active lease. Dispatcher uses 0600 temporary files and the shared default-application `WeChatPusher.send_app_file`; each retry uploads the same saved file again, avoiding stale media IDs. Text and each file part have independent attempts. Latest component status determines outbox completion, so a successful component is never resent on a failed-component retry. Dispatcher stores a private provider-success receipt before acknowledging the API, avoiding resends after callback outages. Provider timeouts remain ambiguous external outcomes and should be reviewed in delivery records.

A dedicated controlled-test command sends only to the selected enabled tenant employee and does not change orders or enable official notifications. The message center displays rules, component logs and retries; no general recipient tab is added. The older equipment and shipping events retain their text behavior.

## Allocation attachment names (2026-10-14)

New attachments use `订单分配_YYMMDDHHMMSS_接收人或承接单位名称.xlsx`. The timestamp comes from the immutable event time in Asia/Shanghai. A single unit identity uses its unit name; salesperson, controlled-test and merged identities use the employee name. Same-name recipients or existing filename collisions append batch/recipient UUIDs; multiple parts retain `_P1`, `_P2`, etc. Invalid path characters are sanitized and the UTF8 basename stays within 255 bytes. Saved attachments and names are reused on retry, including older already-prepared attachments.

The fixed worksheets are 新增订单 (new item snapshots only), 变更订单 (updated existing item snapshots only), and 字段变更明细 (original before/after differences). All four prohibited amount/price fields remain excluded. Only allocation attachments allow Chinese basenames in Dispatcher validation; other file modules retain the English convention. HTTP downloads use an ASCII fallback plus UTF8 Content-Disposition encoding. Triggers, routing, permissions, retries, schedules and rule settings are not changed by the application release; keep the official rule disabled during verification.

## Manual sources and suspended downstream plans (2026-10-14)

Order allocations are maintained only by manual operations and confirmed Excel imports. Per the latest explicit user instruction, allocation/customer-map commands no longer enqueue downstream plan reconciliation; every runtime `plan-projections` entry skips work, including pending events, manual calls and scheduled/replay calls. Existing plans remain retained. Unrelated ERP raw-data collection, shipping/execution jobs and notification routing remain unchanged. Rollback must preserve both restrictions.
