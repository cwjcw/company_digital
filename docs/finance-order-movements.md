# 财务订单金额跨月变更统计

财务中心 → 销售订单统计 → 订单金额跨月变更统计 / 订单变更明细。

现有系统导出34列、月度数据9列和统计大屏保持原功能及254ef45过滤规则；新统计独立增加，不替换旧页面。按用户最新决定，不再核查、评分或展示历史完整性，不调查缺失原因，不以历史缺失阻止发布。

## 金额与时间

用户已确认：接单发生额＝接单基数＋当月可确定有效变更额。接单基数＝当前有效订单金额−该单已计入台账的有效变更额，记在订单月份；它是按当前余额及已有事件重列的计算基数，不宣称历史原始接单金额。跨年按实际月份分配，所以单年发生额可与旧按订单日期余额不同；全期间合计可勾稽。客户及事业部沿用现有财务当前客户对应表重列，ERP部门不替代财务事业部。

变更单使用当前有效审核节点的ApproveDate（上海时区），按稳定变更品项ID＋审核时点幂等；已入账节点保留，不因后续重审而搬移旧月份，同单重审须有不同的前后状态证据才另计；N/V不猜测反向冲回。新增从0到新有效金额，修订为后减前；指定结束后值0，恢复仍受订单头结束状态约束。头CLOSE=1整单排除，任一交货计划CLOSE=1只排对应稳定品项，0/2保留。关闭与改价合并成一次有效状态转移，不能先减价格差再扣原额。

普通DataLog按EventId+订单+品项归组；准备日志不形成第二笔发生额，头和子项不叠加。仅能确定源金额差、不能确定历史有效状态的日志显示源金额差额，计入发生额为“否”。缺金额不写0、不补造事件。整单结束如仅有局部变更行也不猜测整单历史金额。

未来观测到的品项状态变化，有前/后快照且两次观测同一上海自然月时，以“同月状态观测”记录净差，并扣除该区间已由变更单反映的金额；跨月观测不能单凭观测时间认定实际变更月，不伪造历史事件。原始7位源时间保留，页面/Excel显示YYYY-MM-DD HH:mm:ss。

## 权限与表格

四个独立财务资源：finance-e10-changes、finance-e10-movements、finance-e10-movement-departments、finance-e10-movement-customers。系统/财务模块管理员按既有模块规则使用；普通用户必须显式获得对应资源read/export和字段/数据范围，不自动复制旧资源授权，也不修改生产权限数据。

CUSTOM范围在汇总前作用于来源金额腿；导出范围为read∩export，租户RLS强制。每表使用统一KdosDataTable、统一高级筛选/排序/服务端分页及Excel导出；默认100行，上限1000。导出完整匹配结果、英文xlsx文件名，不从当前页生成。金额以Decimal和PostgreSQL numeric计算。初次/清空日期为昨天，可选按日/月/年/自定义。查询缓存60秒，身份/权限与筛选进入缓存键，读取完成失效相关新旧查询。

汇总的客户/事业部辅助字段不是该粒度展示列，由顶部受权上下文筛选；汇总金额高级筛选作用于汇总结果。列宽沿用统一个人视图偏好，按租户/用户/资源/视图隔离。

## 同步与运行

唯一自动入口：FIN-003 n8n每30分钟（Asia/Shanghai）→ SSH → data-operations/e10/sync-finance-movements.sh INCREMENTAL → 容器内Application Command。无新增Timer/cron或应用内部定时器。实际激活与执行证据记录在本机验收文件；模板存在不代表上线。

先调用未改变的FinanceOrdersApplicationService正常更新当前余额，再独立读取台账证据。初次FULL读取现存历史；之后按成功水位重读受影响订单，日志含2分钟重叠并跨月回看；变更单为较小保留集，重读当前版本以捕获审核/撤销变化。源SQL固定READ COMMITTED，工具包保管E10凭据，不读T+或修改标准SQL。

本机flock+租户RUNNING唯一约束/advisory lock防并发；失败保留已发布台账/水位，临时分页待重试。按新成功批次原子发布证据、快照和事件，事件幂等键包含租户/账套；不变重放不增长事件版本/逐事件审计。RUNNING重启/超时标失败，可再次增量补跑或FULL重读，无外发消息。n8n失败需失败执行留痕、失败分支与运维最近成功记录可见；不静默把并发跳过当已同步。

人工补跑：在项目目录执行 data-operations/e10/sync-finance-movements.sh INCREMENTAL；首次/来源重读用FULL。Web财务管理员也可“同步台账”；普通刷新只刷新当前列表，不启动ERP同步。
