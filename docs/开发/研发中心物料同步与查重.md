# 研发中心物料同步与一物多码

## E10 实际字段映射

E10 连接必须通过 `/data/automation/code/work/basci/basic_code` 的 `MSSQLDatabase`。实际数据库为 `E10_6.0.0.1.NEW.CHS`。

E10 字典中的 `GROUP_ITEM` 是逻辑聚合实体，`GI` 是其 Complex 品号信息；生产库中没有同名 `GROUP_ITEM`/`GI` 物理表，实际物料数据表为 `dbo.ITEM`。`dbo.ITEM_GROUP` 是独立的 3 行表，与当前 `dbo.ITEM.ITEM_BUSINESS_ID` 抽样 JOIN 为 0 行，不能作为物料主表或“归类品”来源。

| KDOS 字段 | E10 来源 |
| --- | --- |
| `sourceId` | `dbo.ITEM.ITEM_BUSINESS_ID` |
| 品号 | `dbo.ITEM.ITEM_CODE` |
| 品名 | `dbo.ITEM.ITEM_NAME` |
| 规格 | `dbo.ITEM.ITEM_SPECIFICATION` |
| 备注 | `dbo.ITEM.REMARK` |
| 状态 | `dbo.ITEM.STATUS`、`dbo.ITEM.ApproveStatus` |
| 创建日期 | `dbo.ITEM.CreateDate` |
| 最后修改日期 | `dbo.ITEM.LastModifiedDate` |
| 修改日期 | `dbo.ITEM.ModifiedDate` |
| 创建人 | `dbo.ITEM.CreateBy → dbo.[USER].USER_ID → USER_NAME；无 USER 时回退 EMPLOYEE_NAME` |
| 最后修改人 | `LastModifiedBy` 同上 |
| 修改人 | `ModifiedBy` 同上 |

`归类品` 在 GI 字典和 `dbo.ITEM` 实际列中没有可确认的直接字段，当前保存为 NULL，不以 `GROUP_ITEM_CODE` 或 `ITEM_GROUP` 猜测。

## 水位与同步

增量使用 `LastModifiedDate + ITEM_BUSINESS_ID` 复合游标，并在 reader 内回退 2 分钟重叠窗口；目标通过 source identity 与 content hash 幂等更新。只有整次读取和目标批次提交成功才推进 `rd_sync_runs.watermark_after_*`；失败只记录 FAILED，不写成功水位。

首次上线顺序：先执行 `FULL`，成功后 n8n 每日调用 `INCREMENTAL`。内部接口只接受 `X-KDOS-Internal-Token` 与 `X-KDOS-Tenant-Id`，普通浏览器认证不能调用。

## n8n 调用

Schedule Trigger 的时间只配置在 n8n，不写死在业务代码。HTTP Request 节点：

```text
POST https://<KDOS域名>/api/v1/internal/rd/items/sync
X-KDOS-Internal-Token: <KDOS_RD_INTERNAL_TOKEN>
X-KDOS-Tenant-Id: <KDOS_DEFAULT_TENANT_CODE>
Content-Type: application/json

{"mode":"INCREMENTAL"}
```

首次初始化或人工补全时，受控地将 body 改为 `{"mode":"FULL"}`；该接口不接受 SQL、表名或任意租户参数。
