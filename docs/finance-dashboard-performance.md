# 财务销售订单统计大屏查询

统计大屏继续读取原finance_e10_monthly及订单复核视图，不修改E10/标准SQL、34列原始品项与指定结束规则。2026-10-20业务修正后月度为10列，材料销售单及非Y审核统一排除。

## 查询与分页

客户排名先执行原大屏来源read scope、上下文和客户搜索，再按客户汇总，最后应用排名read scope及金额高级筛选。一次SQL以MATERIALIZED CTE复用分组结果，同时返回total和服务端排序/分页rows，避免count和rows各自重做完整聚合并跨数据库快照。导出额外执行排名export授权及read∩export范围，继续使用平台Excel服务。

Dashboard保持单条金额查询及各维度的同一数据库快照。订单复核结果的基数估计可能严重偏小，PostgreSQL据此选择只按账套合并、订单键作Join Filter的路径，导致大量无效配对。本查询只在既有租户事务内执行SET LOCAL enable_mergejoin = off及SET LOCAL enable_nestloop = off，避免带事业部等条件时又改选嵌套循环，采用完整订单关联键的哈希路径；事务结束或失败后设置自动恢复，不修改数据库/连接池全局参数、不影响别的查询，不新增物化读模型。生产复测须保留带超时的只读EXPLAIN ANALYZE与资源证据，不能假定所有环境计划相同。

管理员异常诊断聚合默认仍返回。页面目前不展示该诊断，因此明确请求includeQuality:false省去独立复核扫描；财务金额、待分类及所有图表指标完整计算，原异常日志入口和API默认响应保留。

## 页面、缓存与新鲜度

排名请求等待公共KdosDataTable首次回调后发出，使用真实用户页大小、空/已应用筛选和排序，不另起默认10行请求；不修改公共组件行为或复制页大小偏好逻辑。

Dashboard及排名查询键包含登录身份/权限上下文、数据revision及完整条件，业务结果保鲜60秒。GET /finance/e10-orders/revision先校验现有大屏read权限，只返回当前租户最近成功财务批次、客户映射版本及实时授权上下文的不可逆摘要，不返回金额或来源行。首次进入、重新进入、窗口聚焦与打开期间每15秒检查；新的成功同步、客户分类或同账号授权变化使revision变化并重新查询；授权摘要改变时立即停止复用上一范围的占位结果，失败批次不会替换成功版本。客户分类保存和前端同步成功同时精确失效revision和相关金额查询。

刷新按钮先检查revision，改变时由新查询键读取一次，未改变时强制刷新当前Dashboard和排名；只刷新显示，不触发ERP同步。没有服务器金额缓存，不以旧金额冒充刚刚查询结果。所有授权仍由每次API实时claims与Query Service执行，前端缓存不构成授权边界。
