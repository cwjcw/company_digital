# 事业部基础计划

## 设计范围与本次规则

本表是订单分配向周计划、工序任务和工序报工投影的业务中间层。本次只约束**新增**基础计划：手工 API 与 Excel 确认新增都必须命中同租户、同订单号、同品项编码的有效订单分配（`archived_at IS NULL`、`allocated_quantity>0`；与当前分配投影准入规则一致，不额外增加订单审核状态条件）。承接事业部必须与分配一致；未填写且精确匹配结果只有一个事业部时由后端补齐，出现多个事业部时要求明确选择。更新、自动同步、既有历史行不受此校验影响。没有数据库结构迁移。

## 字段设计

## 表级与生命周期

- 前端缓存：无；多标签页：否；通用前端事件：无；内嵌子表单/关联子表：无。
- 新增、更新、Excel 导入均通过 Master Plan Application Service；权限由资源操作、字段权限、租户及数据范围联合校验，关键写入保留审计。
- 基础计划由现有 `base-to-weekly` 对账生成周计划；周计划关联工序任务，工序报工只能引用周计划及有效工序任务。
- 不删除既有基础计划和历史报工；本次分配校验仅作用于人工/Excel 新增，不改历史数据、自动投影或更新既有行。
- 表中无附件、无隐藏条件、无公式字段；提示信息由服务端错误返回，不静默清空数据。
- 既有 Excel 导入能力保留。新增行校验与 API 相同；更新行继续执行既有 ID、版本、字段权限、数据范围、审计及事务规则。
