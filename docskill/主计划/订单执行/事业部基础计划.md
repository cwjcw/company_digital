# 事业部基础计划

## 设计范围与本次规则

本表是订单分配向周计划、工序任务和工序报工投影的业务中间层。本次只约束**新增**基础计划：手工 API 与 Excel 确认新增都必须命中同租户、同订单号、同品项编码的有效订单分配（`archived_at IS NULL`、`allocated_quantity>0`；与当前分配投影准入规则一致，不额外增加订单审核状态条件）。承接事业部必须与分配一致；未填写且精确匹配结果只有一个事业部时由后端补齐，出现多个事业部时要求明确选择。更新、自动同步、既有历史行不受此校验影响。没有数据库结构迁移。

## 计划层级及直接数据来源

| 计划/执行对象 | 直接数据来源 | 规则 |
|---|---|---|
| 集团主计划 | 订单分配表 | 确定计划需求及事业部承接归属。 |
| 事业部月度计划 | 订单分配表 | 承接事业部由分配确定；KDOS分配审核状态不是额外准入条件。 |
| 事业部基础计划 | 事业部月度计划 | 出货计划表不是基础计划生成的前置来源。 |
| 事业部周计划 | 事业部基础计划 | 基础计划是周计划唯一直接业务来源。 |
| 周计划工序明细 | 事业部周计划及该事业部有效默认工序配置 | 按现行生产方式与默认路线生成。 |
| 报工系统 | 有效周计划工序任务 | 报工查询基于有效工序任务；实际报工必须来自真实提交。 |

ERP原始订单行ID及历史来源外键可用于追溯、审计和维护，不是计划生成的必需关联。新增基础计划仍按本节前述有效订单分配匹配规则校验；不得额外增加分配审核状态门槛。

## 周计划生成、生命周期与同步规则

周计划生成只以基础计划当前有效业务数据为准。现有五项业务必填字段为：最迟客户交期、最迟评审交期、产品属性、表面性质、生产方式。字段定义及空值语义由后端共享准入定义提供；空字符串和`NULL`均为缺失。未经用户确认不得增加其他业务必填字段或生成准入条件。基础计划有效、数量符合现行规则、五项字段齐全、生产方式要求的工序配置有效，并且没有真实暂停、取消、失效或生产执行冲突时，应自动生成周计划。

基础计划历史来源未核实、缺少历史月度计划外键、月度计划历史来源未确认或非`ACTIVE`、基础计划为`LEGACY_RETAINED`、缺少ERP原始订单行ID、订单分配未审核、生命周期写入开关关闭、已有ERP入库事实、历史同步失败或outbox为SUCCESS/FAILED/BLOCKED/耗尽重试，都不得单独阻止首次生成周计划。来源关联仍用于追溯、审计及独立维护；不得以间接校验、恢复任务、数据库触发器或其他技术流程变相恢复这些限制。真实业务暂停、取消、失效、重复计划、归属冲突及执行冲突仍须正确阻止或隔离；不得强制激活真实暂停或取消的计划。

使用现有事件、reconciliation/outbox及已登记的30分钟`base-to-weekly`调度。自动扫描主动发现当前满足条件且尚无周计划的基础计划；事件、自动和手工同步采用同一准入判断及生成逻辑。历史outbox状态不能永久阻塞当前合格计划。单条计划失败应隔离并保留真实原因，不得拖停其他有效记录；重复运行不得产生重复周计划或工序任务。不得新增重复调度任务。

新周计划使用对应事业部有效默认工序路线；不得用品项专属路线覆盖事业部默认路线，没有有效默认配置时明确阻塞，不回退到通用十工序。按自制、中心外购、外协及自制+外协现行业务规则决定是否生成内部工序任务。ERP入库事实不同于KDOS工序报工事实；仅有入库事实不阻止安全生成缺失周计划及首次工序任务。已有周计划、路线锁定、工序任务、实际报工、ERP入库、审计及其他执行事实必须保留，不得伪造报工或覆盖执行事实。

周计划状态、缺少项和生成提示必须与实际后端准入条件一致，准确区分字段缺失、所需工序配置缺失、等待自动同步、已进入周计划、真实业务阻塞及当前同步失败。不得将“基础计划历史来源待核实”作为周计划生成阻塞。失效的历史错误只留作审计，不能覆盖当前成功状态；已经正常生成的计划不能同时显示当前生成失败，除非确有独立、尚未解决的新失败。

故障排查必须独立核查订单分配 → 月度 → 基础 → 周计划 → 工序任务 → 报工系统的实际数据；不得仅依赖同步候选、outbox SUCCESS、待处理为0、ACTIVE异常为0、任务/API健康或单元测试通过。验收以实际计划及应有任务存在、业务状态正确、符合报工条件的任务可查询为准；共性问题覆盖全部受影响事业部，通过既有 Application Service 安全恢复同类数据。

主计划完整实施约束及13项隔离自动同步回归矩阵见[主计划系统 Skill](../../../.agents/skills/kdos-master-plan-system/SKILL.md)，五个指定历史案例的根因及应保持行为见[回归案例](../../../.agents/skills/kdos-master-plan-system/references/regression-cases.md)。

## 表级与生命周期

- 前端缓存：无；多标签页：否；通用前端事件：无；内嵌子表单/关联子表：无。
- 新增、更新、Excel 导入均通过 Master Plan Application Service；权限由资源操作、字段权限、租户及数据范围联合校验，关键写入保留审计。
- 基础计划由现有 `base-to-weekly` 对账生成周计划；周计划关联工序任务，工序报工只能引用周计划及有效工序任务。
- 不删除既有基础计划和历史报工；本次分配校验仅作用于人工/Excel 新增，不改历史数据、自动投影或更新既有行。
- 表中无附件、无隐藏条件、无公式字段；提示信息由服务端错误返回，不静默清空数据。
- 既有 Excel 导入能力保留。新增行校验与 API 相同；更新行继续执行既有 ID、版本、字段权限、数据范围、审计及事务规则。
